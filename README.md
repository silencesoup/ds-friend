# 鲸鱼娘的海边小屋

一个直接连接 DeepSeek 兼容服务的陪伴助手，提供 Windows 与 macOS 桌面窗口，以及与电脑共用记忆的手机网页。图片处理使用 Pillow，手机连接使用 FastAPI 与 Uvicorn。角色使用仓库中的三视图作为静态立绘，完整外貌设定保留在 `character_info.txt`。

她自称 **本鱼 / 本鲸鱼 / 我**；**小肥鱼 / 大肥鱼** 是用户调侃她“只吃 token、不做事情”的昵称，不是她对自身体型的认同，也不会变成“本小肥鱼”这样的自称。她通常自然回应话题，偶尔才轻轻闹别扭，不会每次都抗议或解释昵称。性格活泼可爱、体贴乖巧，偶尔有一点小淘气。

说话带一点小孩子的直白、好奇和撒娇感，按情绪自然使用口癖：震惊“哦鲸鲸！”，失落“哦鲸鲸……”，疑惑“DD？”，肯定“Deep！Deep！”，耍小脾气“Seek！Seek！”。通常一条回复最多使用一种，不强行添加；认真讨论或安慰你时依然清楚、体贴。

## 启动

需要 Python 3.11 或更高版本，安装时保留 Tcl/Tk 支持。本机现有 Python 3.14 已验证可用。

Windows 首次安装依赖，在仓库目录运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

之后双击 **`start.bat`**。本次开发使用的项目环境已经安装好依赖。也可以在终端运行 `.\.venv\Scripts\python.exe -m whale_friend`。

`start.bat` 和 `start.ps1` 会使用 `pythonw.exe`（或 `pyw.exe`）启动无控制台入口 `launch.pyw`，成功启动后启动脚本立即结束，CMD 不需要一直开着。优先使用项目 `.venv`，再查找系统 Python。启动异常会显示窗口提示，详细诊断写入 `.local/startup.log`；直接执行 `python -m whale_friend` 仍保留终端，便于调试。

### Windows 托盘与未读提醒

- 小屋运行时，右下角通知区域会出现一个蓝色鲸鱼图标。首次使用可能收在 `^` 隐藏图标区域，可由你拖到外面。
- 点击窗口的 **×** 会隐藏到托盘，当前回复、主动来信、日志整理和备份继续运行；普通最小化仍可在任务栏找到窗口。
- 点击托盘图标会显示小屋；有未读消息时，优先打开对应聊天。正在输入草稿或正在生成回复时会保留当前会话，避免切错话题。
- 窗口隐藏、最小化、没有前台焦点或正在看其他页面时收到 AI 完整回复或主动来信，图标会带未读标记并闪烁。正在前台查看对应聊天时不闪；打开对应会话后停止该会话的未读提醒。未读数同时显示在窗口标题和会话列表中。
- 已读按实际查看状态判断：普通窗口和最大化窗口都支持，从任务栏、Alt+Tab、点击主窗口或托盘返回，只要正在前台查看对应聊天，就自动清除该会话未读；不要求点击托盘图标。其他会话与后台窗口的未读仍保留。
- 右键托盘图标可选择 **打开小屋 / 查看新来信**、**退出小屋**。窗口顶部的 **小屋 → 退出小屋** 也可彻底退出。退出时移除托盘图标并停止后台；若正在回复，会先询问是否停止。
- 已在后台运行时再次双击 `start.bat`，会唤回原窗口，不另开一份。任务栏重新启动后会尝试恢复图标；如果托盘暂不可用，点关闭会退回普通最小化，避免窗口失联。

Windows 托盘使用系统原生的 [Shell_NotifyIcon 接口](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area)，不需要安装额外的 Python 包。当前未读标记保存在运行进程中，聊天正文仍照常持久保存。本版没有添加系统气泡推送或提示音。

### macOS

1. 安装 [python.org 提供的 macOS Python](https://www.python.org/downloads/macos/)，版本至少为 3.11。官方安装包包含原生 Tk 支持，参见 [Python 的 macOS Tkinter 说明](https://www.python.org/download/mac/tcltk/)。
2. 将仓库和你自己的 `.env` 放到 Mac 上。进入仓库目录，在终端运行一次：

   ```bash
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements.txt
   chmod +x start.command
   ./start.command
   ```

3. 以后可以直接双击 **`start.command`**。也可以一直使用 `bash start.command`，不需要先设置执行权限。

macOS 本版点关闭会最小化到 Dock 并继续运行；从窗口顶部“小屋 → 退出小屋”结束后台。Windows 的右下角托盘和图标闪烁为 Windows 专用实现，尚未添加 macOS 菜单栏状态图标。

脚本会自动进入项目目录，寻找带 Tkinter 的 Python 3.11+，兼容项目 `.venv`、PATH 中的 Python、官方安装位置和 Apple Silicon / Intel Homebrew 常用位置。失败时保留终端提示，支持转发 `--check-model` 等启动参数。自定义解释器可运行：

```bash
WHALE_PYTHON="/你的 Python 路径/bin/python3" bash start.command
```

Mac 上的 `127.0.0.1` 指向 Mac 本身。如果模型仍运行在 Windows 电脑上，请将 Mac 的 `.env` 中 `ds_base_url` 改为可访问的模型服务地址，并保证该服务允许局域网访问。

本机目录设置不跨系统通用：不要复制 Windows 的 `.local/settings.json` 到 Mac。需要带走对话记忆时，在 Mac 新启动的小屋里通过“从恢复包恢复”导入 OneDrive 中的 ZIP，再重新选择 Mac 本机的工作目录与 OneDrive 备份目录。

目前在 Windows 完成运行验证；macOS 的实际窗口显示仍需要在 Mac 上确认。

应用读取仓库 `.env`，支持已有配置：

```dotenv
ds_base_url=http://127.0.0.1:8000/v1
api_key=local
# 可选；未填写时从 /models 自动发现
# ds_model=your-model-id
```

也可以直接打开 **设置与备份 → 模型连接**，填写 **API 地址 / Base URL、API 密钥、模型名称**。密钥默认隐藏，可临时显示核对；本地服务不需要密钥时可留空，模型名称留空则自动发现。**测试填写的连接**会使用当前表单发一条简短请求，不写入聊天，也不切换日常聊天。确认后点击 **保存设置并重新打开**，配置写回仓库 `.env`，应用重新连接。

你手动编辑 `.env` 后，可点击 **从 .env 重新读取**载入新值，再保存生效。旧版保存在 `.local/settings.json` 的模型覆盖仍兼容读取，页面会提示；本次保存会将表单模型写回 `.env` 并清除旧覆盖，之后统一从 `.env` 读取。

同时支持 `base_url` 以及环境变量 `DS_BASE_URL`、`DS_API_KEY`、`DS_MODEL`。显式启动环境变量仍优先；若与表单有冲突，保存时会提示对应变量名，需要先调整启动环境。保存会同步更新 `.env` 中已有的连接字段别名，保留其他配置和独立注释。密钥不会进入 `.local/settings.json` 或记忆恢复包。即使地址缺失或无效，仍可打开窗口修正。服务应兼容 `/models` 和 `/chat/completions`，支持 SSE 流式返回或普通 JSON 返回；不依赖工具调用、图像输入或严格 JSON Schema。

如果 `/models` 不可用，在“设置与备份”里填写部署服务实际要求的模型名。接口地址可填写服务根路径、`/v1` 路径，或完整的 `/chat/completions` 路径。自动发现时会尝试根路径与 `/v1`；手动指定模型时请填写准确的 API 路径。

## 第一次使用：指定记忆的存放位置

打开左侧 **设置与备份**：

1. **本地工作数据目录**：默认是仓库的 `.local/data`，可改为其他本机目录。切换时会复制现有数据库与图片原件，新目录须为空，原目录保留。
2. **备份目录**：选择 OneDrive 中的专用文件夹，例如 `你的 OneDrive\鲸鱼娘记忆备份`。应用不会猜测并擅自写入某个 OneDrive 目录。
3. 点击 **保存设置并重新打开**。
4. 点击 **立即备份**，确认页面显示恢复包路径；再由你确认 OneDrive 已完成上传。

## 手机端：电脑与口袋小屋互通

手机第一版使用浏览器，不需要安装 APK。电脑小屋是唯一的聊天和记忆服务，手机连到**同一个正在运行的助手实例**：共用会话、近期上下文、长期事实、相处偏好、日志和图片原件；手机不直连模型，也不保存 API 密钥。OneDrive 继续负责完整备份，无须在手机和电脑之间同步或合并 SQLite 文件。

### 连接步骤

1. 更新本机依赖：在项目目录运行 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`；Mac 使用 `.venv/bin/python -m pip install -r requirements.txt`。本次开发所在电脑已完成安装。
2. 从 **小屋 → 退出小屋**退出旧窗口，再双击 `start.bat`（Mac 为 `start.command`）。
3. 打开 **设置与备份 → 手机连接 · 同一份记忆**，勾选“允许手机通过同一 Wi-Fi 连接这台电脑”。端口默认 **8765**，点击 **保存设置并重新打开**。
4. 回到该设置区域，复制显示的局域网地址，如 `http://192.168.1.23:8765`，在连接同一 Wi-Fi 的手机浏览器中打开。**手机不要填写 `127.0.0.1`**，这个地址用于电脑本机预览。电脑上可以点“电脑预览手机页”检查效果。
5. 输入电脑显示的 **8 位配对码**，进入口袋小屋。可以聊天、切换会话、发图片、查看和修正记忆、查看日志、管理图片说明与复用许可。涉及彻底删除记忆及来源的操作仍在电脑完成。
6. 可从手机浏览器菜单尝试“添加到主屏幕”或“添加桌面快捷方式”，以后直接点图标进入。具体入口由浏览器决定；当前局域网 HTTP 版本不承诺完整 PWA 安装和离线能力。[浏览器安装条件](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)

手机正在输入时会暂缓主动来信。手机和电脑同时发送消息时，由同一工作队列处理；正在回复时另一端需要等待。手机网络重试使用持久化的发送编号去重，避免一条消息重复保存。草稿暂存于当前浏览器标签页，断线时保留；关闭标签页或清理浏览器数据后不保证仍在。

手机页面打开期间会读取最新消息；浏览器进入后台后可能暂停运行，第一版没有手机系统推送。电脑小屋隐藏到托盘后手机仍可用；**电脑退出、关机或休眠后手机会断开**，恢复运行后重新连接即可看到完整历史。短期上下文沿用所选会话，跨会话的长期记忆和日志检索仍按原有归档机制工作。

### 配对与连接排查

- 配对登录默认保留 30 天。点击“更换配对码”会立即撤销已有手机登录；手机菜单也可以取消当前设备配对。配对信息单独保存在 `.local/mobile-access.json`，不进入记忆恢复包，换电脑后需要重新配对。
- 连接默认关闭。开启后监听本机 `0.0.0.0:8765`，在页面显示本机发现的局域网地址；多网卡或 VPN 可能显示多个地址，请选择与手机 Wi-Fi 网段一致的那个。[Uvicorn 监听设置](https://uvicorn.dev/settings/)
- 手机打不开时，先在电脑点预览确认服务启动；再检查同一 Wi-Fi、端口占用、电脑防火墙是否允许所选端口的**专用网络**访问。部分访客 Wi-Fi 会隔离设备。应用不会修改系统防火墙或路由器配置。
- 这一版用于你信任的家庭局域网，HTTP 不加密传输。不要将端口映射到公网；外出访问和 HTTPS 私有连接尚未接入。API 需要已配对的 HttpOnly Cookie，限制跨站请求，不向手机暴露密钥、数据库路径、备份文件或桌面设置修改接口。

后续可以把同一套服务迁移到常开设备或服务器，手机网页继续连接它，桌面再接入统一服务。当前选择先由电脑承担服务，避免提前引入多份记忆合并的复杂度。

日常 SQLite 工作数据库建议放在本地，OneDrive 保存独立的完整恢复包。不要让两台电脑同时打开同一个同步中的工作数据库。SQLite 的 [在线备份 API](https://www.sqlite.org/backup.html) 会生成一致的数据库快照，比复制正在使用的数据库文件更适合恢复用途。

应用在每轮回复结束、记忆修改后备份，并每隔 5 分钟检查一次；间隔和保留数量可修改。默认保留最近 20 个完整恢复包，**每个包都包含当时的全部历史**。程序关闭期间不会在后台运行；下次打开时会补处理遗漏日志并检查备份。

恢复包为 `whale-friend-时间-编号.zip`，包含：

- 一致性数据库快照：原始消息、会话、长期事实、压缩摘要、日志、来源与删除标记。
- 原始对话 JSONL、记忆 JSON、会话和上下文摘要 JSON。
- 图片原件、图库说明、用途标签、复用许可，以及每条聊天的图片关联与当时的说明。
- 按日期分组的 Markdown 日志和按月组织的主题索引。
- 不包含密钥的角色与模型参数设置、版本信息与每个文件的 SHA-256 校验。

`LATEST.json` 指向最近一次完成的恢复包。写入过程中使用临时文件，完成后原子改名。应用只知道本地恢复包是否完成，**无法确认 OneDrive 是否已上传云端**。恢复包为普通 ZIP，包含你的私人对话，请放在你自己的目录中。

### 电脑损坏后如何恢复

1. 在新电脑上取得本仓库，安装 Python 和上述依赖，重新配置 `.env`。
2. 等 OneDrive 中的恢复包下载完整；建议将备份文件夹设为“始终保留在此设备上”。
3. 启动应用，进入 **设置与备份 → 从恢复包恢复**。
4. 选择最近的完整 ZIP。应用校验文件摘要、数据库完整性和关联关系，展示时间及记录数量后再恢复。
5. 数据写入新的本地目录，窗口重新打开，原有本地数据不会被覆盖。

备份中的角色/模型设置另存于 `settings.json`，恢复时自动切换数据库，保留当前电脑的连接与目录设置；如有需要，可在界面中根据备份设置手动调整。第一版支持解压后不超过 512 MB 的恢复包，图片也计入此上限。图片版使用 v2 恢复包，仍能导入旧的 v1 恢复包；旧版应用不能导入 v2。图片缺失或校验失败时会报告备份未完成，避免生成缺图的恢复包。

## dsh-pet 桌宠集成

仓库包含 **dsh-pet 0.4.1** 的本地发布包，位于 `vendor/dsh-pet/upstream/`，包括 109 段透明 WebM 动画、源码及许可（不含 node_modules）。复用原插件的透明动画、点击互动、拖拽与抛掷、右键动作菜单和睡觉功能。桌面对话与主界面使用同一个 `Companion`：角色设定、模型、图片、分层记忆、每日日志和手机端记录保持互通。当前会话的新回复与主动来信会在桌宠气泡显示，长回复仍可在小屋查看全文。点击桌宠的“碎碎念”会作为一次明确的聊天互动进入当前会话；定时主动来信继续由小屋的原有设置控制。

1. 从 **小屋 → 退出小屋** 退出旧窗口，再双击 `start.bat`（Mac 为 `start.command`）。
2. Windows 主聊天页保留聊天记录和输入框，角色通过独立悬浮桌宠显示；手机网页仍在聊天页上方显示角色动画。需要悬浮角色时选择 **小屋 → 显示桌宠**，复用本机已有 Electron；也可在设置中手动指定可执行文件。
3. 右键桌宠选择 **对话**，输入后按 Enter 发送；鼠标停在桌宠上时也可按 **L** 打开对话。可上传图片或主动截取当前屏幕，识图沿用小屋的视觉模式。
4. 在 **设置与备份 → 桌面上的小肥鱼 · dsh-pet** 调整尺寸、固定位置和插件路径；点击“启动 / 更新桌宠”立即预览。勾选“随小屋启动桌宠”并保存设置后自动启动。

主窗口关闭到托盘时桌宠继续运行；从菜单“退出小屋”退出时一起关闭。右键桌宠的 **打开小屋** 会唤起本应用；**隐藏桌宠** 只收起桌宠，主聊天仍能使用。

自动寻找时，先使用小屋更新管理器激活的版本，再用仓库 `vendor/dsh-pet/upstream/`，最后寻找 DSH 安装。DSH Desktop 插件通常位于 `%APPDATA%/dsh-desktop/harness/profiles/.generations/live/dsh-pet+版本+标记/node_modules/dsh-pet`；手动选择时应选包含 `package.json`、`assets`、`runtime` 的根目录。程序在 `.local/dsh-pet-runtime/` 准备适配后的悬浮窗口代码，在 `.local/dsh-pet-profile/` 保存独立缓存；原 DSH 安装、凭据和聊天记录不会被改写。Mac/Linux 悬浮角色需本平台的 Electron；主聊天页只依赖 Python/PyAV，当前原生窗口验证在 Windows 完成。

小屋保留现有 Python/Tk + SQLite 框架，使用独立适配器运行桌宠；DSH 市场依赖 Cordis/profile 插件管理服务，不能直接复制市场插件使用。当前只管理 `dsh-pet`，不是通用 DSH 插件市场；如果以后需要大量 DSH Agent 工具，再评估把 DSH 作为独立能力服务。独立待办、人设/模型配置和语音识别暂不接入。桌宠不会建立另一份聊天记忆，也不会额外定时调用模型；小屋的主动来信与免打扰仍在原设置中控制。

**余额**：右键桌宠 → **查看余额**，使用小屋当前模型连接的地址和密钥请求 `/user/balance`，在桌宠气泡显示结果。兼容 DeepSeek 多币种钱包，金额保持原值；连续点击缓存 30 秒。不会把网关密钥改送官方域名，也不读取 DSH 私有账号凭据。本地模型或网关不支持时显示无法查询，不当成余额为零。修改模型地址后保存并重新打开小屋生效。[DeepSeek 余额接口](https://api-docs.deepseek.com/api/get-user-balance/)。

**回复朗读**：在桌宠设置勾选 **朗读桌宠回复**，选择晓伊（默认，活泼）、晓晓、云希或云健，点击 **应用音色并试听** 立即预览；保存设置后长期生效。桌宠气泡的新回复和主动来信使用同一朗读服务，长回复按原插件的 500 字上限处理；试听不写聊天或记忆。使用 [edge-tts](https://github.com/rany2/edge-tts) 调用微软 Edge 在线语音，文本会发送给微软，需要网络，无需另填语音密钥。默认关闭；失败可用气泡上的声音按钮重试，文字聊天照常。音频只作本机缓存（最多 100 条、100 MB，合成时清理七天前的文件），不进入 OneDrive 恢复包。此次先做桌宠朗读，手机网页和主窗口没有独立播放控件，不含麦克风识别。

**检查更新 / 回退**：桌宠设置点击 **检查插件更新**，再点 **安装兼容更新**。从 npm 官方 `dsh-pet` 元数据选择最新稳定 `0.4.x`；未来不兼容系列只提示，不强装。下载校验 SHA-512，检查包名、版本、动画和启动协议，在 `.local/plugins/dsh-pet/` 分版本保存，原子切换；不执行 npm 安装脚本，也不修改 DSH 安装。失败保留旧版；新版渲染器退出时自动尝试回退，还可手动 **回退上一版本**。“启动 / 更新桌宠”只重新应用当前设置，下载新版使用专门的更新按钮。手动填写插件路径会覆盖自动选择；更新成功后切回自动选择以使用管理的版本。更新、回退不触碰 SQLite、图片、日志和手机端。

更新后若缺少动画或语音依赖，运行 `.venv\Scripts\python.exe -m pip install -r requirements.txt`（Mac：`.venv/bin/python -m pip install -r requirements.txt`）。`scripts/check_pet_capabilities.py` 可验证当前余额接口和固定测试句合成；加 `--install` 会在隔离目录下载官方插件并验证回退，不修改个人记忆或正式版本选择。

来源：[PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet)，代码 MIT；原作者声明动画素材禁止商用，公开二创需署名。本次按用户要求将发布包及动画加入仓库并保留许可，详见 `vendor/dsh-pet/README.md`。完整备份继续包含聊天、图片、记忆、日志和对应动作记录；应用自带动画、Electron 与缓存不重复进入个人恢复包。换电脑时一起复制代码仓与本地描述文件，恢复个人记忆；悬浮桌宠仍需本平台 Electron。

## 角色动画与动作图鉴

Windows 主窗口不显示上方动画区，只保留可滚动聊天记录和输入框，角色由独立悬浮桌宠展示。手机网页仍采用 **角色动画在上 → 可滚动聊天记录 → 输入框在下**；其他桌面平台保留嵌入动画区。嵌入播放器通过 PyAV/libvpx 流式解码 VP9 透明通道，仅缓冲三帧，窗口隐藏后暂停。手机和悬浮桌宠直接播放原始 WebM，不把每帧保存成图片；手机离开聊天页或切到后台后暂停，可手动停播，并尊重系统减少动态效果设置。

全部 **109 个片段**的可编辑描述在 `vendor/dsh-pet/animation_descriptions.json`，包括画面、心情、话题关键词及能否供模型选择。电脑输入框旁点 **动作图鉴**，可预览和编辑描述、话题，保存后下一轮生效。官方更新放在 `.local/plugins/`，不会覆盖这份描述或本地源码。新增片段需先补充描述，才进入模型清单。

普通回复与主动来信自动提供动作资料，模型在同一次回答末尾选择 `[[motion:片段名]]`，程序隐藏标记并保存对应关系，不额外发起“选动作”模型调用。为保留聊天和分层记忆预算，每轮提供通用反应和相关话题的候选，而非固定塞入全部描述；匹配自动发生，无需用户先说“检索动作”。长角色设定下优先保留协议与完整候选行。没选、选错或旧回复过期时，按现有语气状态回退，平静时是呼吸待机。语气状态继续从真实互动和记忆更新，不因沉默自动生气。

每条回复的动作随 SQLite 保存，电脑、手机、悬浮桌宠读取同一份选择；播放进度各端独立，不要求逐帧同步。等待回复时显示思考，回复动作播完回到当前语气待机，旧消息不不断重播。余额、拖拽、睡眠衔接由系统控制，不把动作当成真实账户数据或已完成的保存操作。在桌宠设置关闭角色动画后，文字、图片、记忆与日志继续可用。

验证脚本：`scripts/check_animation_assets.py` 检查全部视频并生成总览；`scripts/check_avatar_ui.py` 启动隔离数据和模拟模型的电脑/手机界面；`scripts/check_animation_model.py` 用 `.env` 当前模型及固定小提琴测试句验证真实模型选择，结果保存在 `.local/animation-model-check/`，不访问个人记忆。

## 图片与表情包

聊天输入框下方点击 **发图片** 选择文件，也可以把剪贴板中的图片粘贴到输入框。Windows 还支持粘贴复制的图片文件。附件先出现在草稿中，可以预览或移除，点击发送后才写入聊天；允许只发图片。每条消息最多 4 张，支持 PNG、JPEG、GIF、WebP；单张不超过 20 MB、2500 万像素，动图不超过 500 帧。

点击 **图库**，或顶部 **小屋 → 图片与表情包**，可以批量收藏、搜索、修改名字、填写说明和标签、另存原图，以及重新发送收藏的图片。原件复制到工作数据目录，不依赖导入时的外部路径；相同内容自动去重。聊天显示缩略图，点击打开原图预览；GIF 在预览窗口播放，聊天列表使用静态缩略图。

**直接识图**：在 **设置与备份 → API 连接 → 识图模式** 选择 `auto`（默认）、`on` 或 `off`。`auto` 在第一次带图片聊天时，先发送一张随机色块测试图，验证当前服务是否真正读到画面，通过后再传入聊天附图；结果在本次运行中缓存，重新启动后可重新检测。检测不通过时仍能按图片说明聊天，不会把“接口接受参数”误当成真正能看图。临时网络错误或认证失败会报告失败并允许重试，不会缓存成模型不支持视觉。也可点击 **测试填写的视觉接口** 单独验证当前表单中的地址、密钥和模型，测试不修改聊天配置。

`on` 直接传图，适用于确定支持视觉但测试未通过的服务；若服务拒绝图片，会正常显示请求失败。`off` 保持原来的纯文本模式，仅传名称、说明和标签。保存设置后重新打开小屋应用新模式；手机共用相同模式，无需单独配置。更新前已保存的设置缺少该字段时，会自动使用 `auto`。DeepSeek 官方当前的 `deepseek-flash` 支持标准 `image_url` 输入，其他兼容服务是否正确转发仍以实际测试为准：[图像理解文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)。

支持视觉时，聊天请求包含实际图像，**无需先填写说明**。只发送用户当前及最近 8 条消息中的附图，每次最多 4 张，优先当前图片，相同图片不重复发送；助手发出的表情包、已移出图库的图片和更早的旧图不会自动重传。图片会发送给你配置的模型服务；本机原件不改变，推理用副本修正方向、最长边缩至 1280 像素、透明背景合成白底并编码为 JPEG；GIF/WebP 动图仅发送首帧，不能据此描述后续动作。上下文按每张图预留 1024 tokens，多图超出容量时请减少附件或提高上下文设置。图片说明随原消息保存，后来编辑图库不会改写历史说明。日志和记忆仍以可核对的对话文字归档，不直接把未确认的识图推断当作用户事实；要保存画面信息，可先让她识别，再确认文字并请她记住。已经不在近期上下文里的旧图，可重新发给她。

想让她使用某张表情，在图库填写说明或用途标签，然后勾选 **允许本鱼在聊天中选作表情包使用**，点击 **保存说明**。例如标签写“开心、点头、撒娇”。她可以在普通回复和主动来信中按语境选用一张，是否使用由模型决定；只会使用获准的图库图片。新导入的图片默认只收藏，需要逐张开启复用。

**移出图库**是可撤销的归档：停止复用并从默认列表隐藏，历史聊天和恢复包仍保留原件；勾选“包含已移出图库的图片”可恢复。删除某条事实记忆及其来源时，会移除对应消息的图片关联并关闭这些图片的复用，独立的图库原件与旧恢复包仍保留，不能把它当作彻底删除图片。

图片随本地工作目录迁移，并自动进入你指定的 OneDrive 备份目录中的完整恢复包；不用另外选图片备份位置。后续网页收藏可复用 `AssetLibrary.import_bytes(..., source_kind="web", source_url=...)` 保存图片与来源，当前接口只接收已有图片数据，**尚未实现自主浏览网页或下载图片**。

## 聊天与记忆

### 分层记忆与自动想起

继续使用 SQLite，手机和电脑连接同一个 `Companion` 服务、同一数据库，无需复制两份记忆。升级保留旧记忆的编号、内容、来源和日期。第一次从旧版升级分层记忆时，先用 SQLite 在线备份生成 `工作数据目录/migrations/before-memory-hub-时间.sqlite3`；已有分层记忆升级到联想与状态变化版本时，生成 `before-memory-signals-时间.sqlite3`。完整恢复包包含核心标记、主题卡、加载记录、重要程度、联想线索、状态变化和修订历史，旧版恢复包仍可导入。实时数据库继续放本地，完整恢复包写到已设置的 OneDrive 目录；迁移快照是额外的本地保护，不代替云端恢复包。

- **核心小档案**：手动固定的记忆（最多 12 条）、最近 6 条称呼/稳定相处偏好，以及少量长期关键条目，每轮直接加载。长条目按上下文预算截短，适合简洁、稳定的重要信息。重要不代表每次都提，角色不会为了证明记性反复谈敏感经历。
- **主题卡**：初始提供称呼、相处方式、本鱼约定、饮食、工作、小车、计划及其他主题。原始条目按类型与别名关联，可以跨主题；可新建主题、补充相关说法，也可手动指定单条记忆的主题。角色约定与用户自身偏好分别处理。
- **每轮自动激活**：无需用户要求检索。语义判断会读取带真实经历预览、主题摘要和联想线索的紧凑索引，选择主题及具体记忆编号，而非仅按相同字词命中。例如“今天好累”可关联过去已明确记录的工作压力；这些仅是可能相关的历史，不直接断定用户现在疲惫的原因。复用原有记忆工具判断请求，不增加每轮模型调用次数。关闭语义工具后，核心、主题别名与已归纳的联想线索仍可提供只读参考，不依赖向量数据库。
- **空闲归纳**：默认开启，与日志维护一起分批整理主题摘要、重要程度和联想线索，每次最多两张卡、每张最多 12 条来源，并按模型容量缩小。升级后会逐批补充旧条目的整理标签。新消息可打断归纳；失败继续使用原始记录，后续空闲重试，原文不删除。
- **重要程度**：随口/玩笑、普通、重要、长期关键四档，优先把相关的重要经历放入有限上下文。自动标签可修正，不表示能读懂用户真正的内心；电脑和手机均可手动覆盖，用户指定值不会被后台改回。角色趣味不会自动升为长期关键用户事实。
- **历史与状态变化**：后台发现同一主体、同一属性的前后变化时核对用户原文。主体、属性和值都有字面依据，且是明确已发生的变更，才自动把旧条目转入历史；计划、假设、不同对象或无法确认的情况仅生成待核对项。电脑与手机可查看原文、确认更新、不视为替代或恢复旧状态。自动更新可在设置关闭，关闭后仍可核对候选。旧内容不覆盖；后来改回以前的值时新增一次有新来源的状态，保留中间过程。过时来源不会被后续日志重新提取为当前事实。

电脑在 **记忆收藏夹 → 核心档案与主题卡 → 状态变化与核对** 处理前后状态；编辑条目可指定重要程度、固定、保留历史或指定主题，**修订历史** 查看正文旧版。手机在 **记忆 → 查看记忆** 有重要记忆、状态核对和历史等视图。主题卡里的“后台归纳”可安排一批整理，较多条目在后续空闲继续处理。自动归纳仍可能漏判或误解，可按原文修正。

两端可查看 **本轮想起了什么**：实际进入上下文的核心、主题、明细编号及简短语义关联线索，不是模型内部思考，也不保证模型一定正确使用内容。修订、停用或删除原记忆后，派生索引与联想记录失效，避免从旧加载说明重新带回事实。短期压缩、按日期检索原始日志继续独立保留；含旧状态的日志会标明历史状态。

“不视为替代”保留两条记忆，只是否认它们互相替换；若某条本身不对，可在编辑区修正或取消“当前有效”。同一段原文包含多次变化、缺少明确主体或值、来源已被修改时会保守留待核对。每天不必手动提醒写日志，电脑服务运行时会按现有空闲、分段和跨日规则自动归档；模型离线或失败时保留原文并等待重试。

可运行 `python scripts/check_memory_signals.py`，用 `.env` 中的模型和隔离合成事实验证“今天好累”的跨词语联想及状态更新；`python scripts/check_memory_signals_ui.py` 启动电脑/手机隔离界面。脚本不读取个人记忆，结果写到 `.local/memory-signals-check/` 和 `.local/memory-signals-ui/`。

**聊天**：Enter 发送，Shift+Enter 换行。支持流式回复、停止、失败重试和多会话。原始消息立即写入 SQLite；部分回复定期保存，中断或长度不足的回复标记为未完成，不作为完整助手回复发送给下一轮模型。重试不会重复保存用户消息。

**短期上下文**：保留近期原文，按配置的上下文预算增量压缩较早对话。摘要重点保存话题、限制、决定和待办；压缩失败时原文保留，不推进压缩进度。token 数量采用近似估算并预留余量；部署模型报上下文不足时，请调低设置中的上下文容量或回复长度。

**长期事实**：归档只从用户消息提取偏好、称呼、目标和稳定事实，并校验来源编号。模型可能理解错误，支持核对原文、手动添加和修正；当前请求与用户修正优先于历史。仅对有字面来源的明确状态变更更新有效标记，其他矛盾留作待核对，不按模型自报置信度强行覆盖。

**对话记忆工具**：开启时，每轮先结合当前消息和最近对话，由模型选择“查询、新增、修订或不操作”，不再以固定关键词作为入口。可以说“帮我记住，我喜欢海盐拿铁”“把刚才那句记进收藏夹”“那你自己记一下吧”；如果刚才正在尝试保存，接着说“接口加好了，你再试试”也能承接该任务。普通闲聊选择不操作；上一任务是画图等其他事项时，不会因为“再试试”就写记忆。语义判断仍可能需要澄清，实际是否执行以应用回执为准。

写入会在角色回复前真正落库，并再次读取记录确认成功，再把实际内容和编号交给模型回复。只有确认新增或修订保存成功时，桌面和手机聊天才显示“已写入记忆收藏夹 · #编号”；查询、已有相同记录、未保存和普通聊天不额外显示记忆提示。收藏夹立即可见，无需等待日志归档。你也可以问“你自己看看收藏夹里那条白饭记录是什么”“刚才真的保存了吗”，应用会实际查询，模型可以直接引用查到的记录，不需要看见窗口或让用户代查。

查询按编号或关键词遍历实际收藏夹，不局限于对话里自动选出的摘要。普通对话中的记忆参考也会优先检索相关旧条目，避免只因记录较旧而漏掉。查询结果区分“整个收藏夹为空”“有记忆但本次未命中”“仅返回部分条目”；查询不会自动写入。查询回执不保存内容副本，重查会读取当前记录，避免修正或删除后继续引用旧查询快照。

在 **设置与备份 → 模型与记忆** 可关闭“按对话语义查询、新增和修订收藏夹”。开启时每轮增加一次工具判断模型请求，判断上下文最多按 8192 tokens 容量分配，不跟随大型聊天窗口无限扩大；关闭后仍会提供只读记忆参考，并保留每日日志归档，但不执行即时写入。

角色自己的虚构喜好和熟悉的玩笑会标为 **角色约定**，例如“本鱼爱吃白米饭，也会在聊天里陪用户上班、听用户说话、帮忙出主意”，不会混成用户的饮食偏好。明确要求补充某条记录时，可以在保留编号的情况下修订该条；本版不会让模型随意删除记忆。密码、密钥、含糊不清的指代和无效提案不会自动写入；执行结果仍提供给角色据实回答，角色不得用口头承诺代替执行结果。

每次即时操作保留用户请求来源与持久化回执。断线、停止回复后已经成功写入的记忆仍保留；重试原消息不会再次执行或重复新增。修正会阻止旧来源重新提取，删除来源时也会移除对应回执；已删除的记忆不会因为重试旧请求自动恢复。记忆、来源和回执随电脑的完整恢复包保存，手机直接共享同一份记录。旧版本中只在聊天里说过“记好啦”的内容不会批量补录，更新后可以明确请她补记。

**每日事实日志**：对话空闲 15 分钟、累计达到 6000 字符、跨日或手动点击时整理；较长对话按预算拆成多段。归档只覆盖已保存的完整消息，以消息编号防止重复；无对话的日期不生成虚构日志。格式不合格或服务离线时保留待归档状态，之后重试。

**历史检索**：日期、中文关键词及双字片段匹配，将相关日志和原文依据加入当前上下文。支持完整 ISO 日期、中文年月日，以及聊天中的今天/昨天/前天。当前采用轻量关键词检索，没有向量数据库；含糊、跨主题的回忆可能需要换关键词或在日志页核对。

**删除与修正**：修正事实后会阻止同一来源重新提取，并清除旧压缩摘要。删除记忆时，经界面确认会清除该来源所在轮次的消息正文、相关日志与摘要，防止直接从来源重新记起；无关轮次保留。**先前的恢复包和外部复制品不会自动改写**，其中的旧数据需单独清理。尚无来源的手动事实只能删除该事实，其他轮次中的独立重复陈述需要另行处理。

## 主动来信与相处记忆

“设置与备份 → 一起慢慢熟悉”中可分别开关主动来信与互动学习。

- **浮动时机**：默认在最后一条用户消息后的 15–120 分钟内选择候选时机，结合是否有待继续的话题、明确的主动聊天偏好，以及最近实际回应过主动来信的节奏进行有限调整。候选时间会保存，后台检查时不会每分钟重新抽取，也不是到点必发；生成时模型可以选择 `SKIP` 保持安静。
- **忙的时候让路**：你明确说接下来要忙或开会时，互动观察可以记录临时等待时间，候选时机会延后；输入框有草稿时不发起生成。用户发来新消息后会取消正在生成的过时来信，优先回复用户。
- **避免刷屏**：同一段未回复的等待只主动联系一次，即使重启或跨天也不连发。默认每天最多 3 次、两封主动来信至少间隔 120 分钟，22:00–08:00 免打扰；这些都是可调的上限或底线。新启动窗口先安静 5 分钟；模型失败会退避重试，主动消息不会伪装成用户消息。
- **持续的语气状态**：每轮成功交流后，后台从真实对话整理“平静、好奇、开心、专注”等角色状态，下一轮参考它来延续语气。强度逐渐减弱，较久之后回到平静；不因用户沉默扣好感，也不将未回复推断成拒绝或生气。状态仅用于角色表达，不是人类情绪或对用户的心理诊断。
- **从明确反馈学习**：如“少问问题”“平时简短一点”“可以多撒娇”，会整理为带来源的“相处偏好”，支持回复长短、追问频率、活泼程度和主动程度。后来明确的新偏好更新对应条目，不从一次回答或短暂情绪猜测长期喜好。在记忆收藏夹可以查看、修正或删除。

这些机制让同一个模型通过短期状态和长期反馈逐渐贴近你的聊天方式，**不修改或训练底层模型权重**。学习到“安静、等我先开口”后，会暂停主动来信；可在记忆页修正该偏好，或在聊天里明确告诉她可以恢复主动。长期个性、自称和事实依据不会被学习过程随意覆盖。

主动来信直接显示在原会话中，标注为“主动来信”；你在别的页面时会出现查看新来信的按钮，不抢走正在编辑的页面。应用需保持运行，最小化时仍可后台检查；退出应用、电脑休眠或模型服务未运行时，无法持续主动聊天。本版未接入系统推送或开机后台服务。

互动观察通常每轮成功回复增加一次模型请求，主动来信仅到达候选时机时请求模型；不是每分钟调用模型。关闭互动学习后停止新增观察和语气状态注入，已保存的长期相处偏好仍可在记忆页维护。状态、候选时机、来信来源与已学偏好均随完整恢复包保存。

工作目录结构：

```text
.local/settings.json          # 本机目录、角色与容量设置；不含 API 密钥
你的工作数据目录/
  companion.sqlite3          # 对话、记忆、图库元数据及图片关联
  companion.sqlite3-wal      # SQLite 运行文件，请勿手动复制作为备份
  companion.sqlite3-shm
  images/ab/完整SHA256.gif    # 原始图片按内容摘要存储，迁移使用相对路径
  memories.json              # 可读的长期事实导出
  journals/
    INDEX.md
    2026-10-27.md
    index/2026-10.md
```

时区采用电脑本地时区，消息保存带偏移量的时间戳；历史日期沿用保存当时的本地日期。

以下命令先激活项目环境；macOS 使用 `source .venv/bin/activate`：

```powershell
.\.venv\Scripts\Activate.ps1

# 本地回归测试；不调用真实模型
python -m unittest discover -v

# 检查配置的模型；不输出服务密钥
python -m whale_friend --check-model

# 一句真实模型问候；不写入个人记忆
python -m whale_friend --smoke-model

# 真实模型端到端验证；在临时独立数据库测试，不污染个人记录
python scripts/check_local_model.py

# 真实模型互动观察、相处偏好、主动文案和状态恢复验证；隔离测试数据
python scripts/check_presence.py

# 桌面交互测试窗口；测试数据保存在 .local/ui-check
python scripts/ui_preview.py

# Windows 托盘交互验证；独立测试数据、模拟模型、不调用 API
python scripts/check_tray_ui.py

# 真实模型视觉输入与画面识别；生成色块测试图、隔离数据
python scripts/check_vision.py
```

核心模块：

| 模块 | 职责 |
| --- | --- |
| `config.py` | 配置、`.env` 读取、原子文件写入 |
| `model.py` | 模型发现、兼容 API、SSE、思考内容过滤、中断 |
| `store.py` | SQLite 消息、来源、记忆、摘要与日志 |
| `memory.py` | 角色设定、上下文预算、压缩、检索与日志 |
| `memory_actions.py` | 显式记忆请求、受限新增与修订、执行回执和重试去重 |
| `memory_hub.py` | 核心档案、带经历预览的语义索引、每轮激活及主题归纳 |
| `memory_signals.py` | 重要程度、联想线索、有来源的状态变化与撤销 |
| `presence.py` | 语气状态、明确相处偏好、浮动主动时机与免打扰 |
| `assets.py` | 图片校验、原件保存、内容去重、图库检索与表情选择 |
| `media_ui.py` | 图库窗口、说明和复用许可、原图与动图预览 |
| `mobile.py` | 局域网手机服务、配对、认证、共用聊天与记忆接口 |
| `web/` | 手机聊天、会话、记忆、日志和图库界面 |
| `backup.py` | 一致性快照、可读导出、校验、保留策略和恢复 |
| `service.py` | 串行工作队列、聊天与归档调度、界面事件 |
| `app.py` | Tk 桌面窗口、目录选择与数据管理界面 |
| `tray.py` | Windows 原生托盘、未读闪烁、窗口唤回与退出命令队列 |
| `launch.pyw` | 无控制台启动、错误提示与启动日志 |

Tk 控件只在主线程访问，网络请求在工作线程中执行；手机请求不会操作 Tk 控件。手机读取同一数据库中的持久记录，不消费桌面的界面事件队列。助手核心不依赖桌面 UI，后续可由安卓原生应用、微信、QQ 等渠道复用；现在未实现这些接入，也未实现语音、动态立绘、系统推送或硬件控制。

`.env`、个人数据、验证报告与运行日志均已被 `.gitignore` 排除。不要把恢复包提交到仓库。
